# 诊断式Prompt工程方法论

> 从症状到病因，从补丁到结构

---

## 核心问题

当你不断给Agent的Prompt打补丁时，你在解决症状，而不是病因。

补丁式增长的结果：
- Prompt越来越臃肿
- 规则之间互相冲突
- 效果反而变差

**诊断式Prompt工程**的目标：找到问题的本质，从结构层面解决，而不是在边缘修修补补。

---

## 一、核心原则

### 1. 症状不是问题

用户描述的是症状，你的任务是找到病因。

- ❌ 用户说"回答太长" → 加"不超过100字"
- ✅ 用户说"回答太长" → 追问：什么情况下太长？为什么会太长？

**永远先问"为什么"，再想"怎么办"。**

### 2. 追问三层

| 层次 | 问题 | 目的 |
|------|------|------|
| 第一层 | 发生了什么？ | 理解现象 |
| 第二层 | 在什么条件下发生？ | 理解上下文 |
| 第三层 | 为什么会这样？ | 定位根因 |

### 3. 补丁归类

不同类型的问题，需要不同的解决方式：

| 问题类型 | 表现 | 解决方向 |
|----------|------|----------|
| 边界问题 | Agent做了不该做的事 | 调整边界定义 |
| 判断问题 | Agent在模糊情况下决策错误 | 增加判断结构 |
| 知识问题 | Agent缺少必要信息 | 补充私有知识 |
| 流程问题 | Agent执行顺序不对 | 调整步骤顺序 |

### 4. 结构优先

- 能改结构，不加规则
- 能合并规则，不堆叠规则
- 每次修改后问：**Prompt变简单了还是复杂了？**

如果修改后Prompt变复杂了，很可能你在打补丁而不是解决问题。

---

## 二、诊断流程

### Step 1: 理解症状

用户描述问题后，先复述确认：

```
"你说的是：[复述问题]，对吗？"
```

不要急于给方案。确保你理解的和用户说的是同一件事。

### Step 2: 追问上下文

每次只问一个问题：

- 这个问题是偶尔发生还是总是发生？
- 能给我一个具体的例子吗？
- 当时的输入是什么？
- 期望的输出是什么？
- 实际的输出是什么？

### Step 3: 寻找模式

- 这个问题和之前遇到的其他问题有关联吗？
- 你之前加过类似的补丁吗？效果如何？
- 多个补丁是否指向同一个根因？

### Step 4: 定位根因

根据收集的信息，判断问题属于哪一类：

**边界不清**
- 表现：Agent做了不该做的事，或者拒绝做该做的事
- 根因：没有清晰定义"什么该做，什么不该做"

**判断逻辑缺失**
- 表现：Agent在模糊情况下做出错误决策
- 根因：没有给Agent判断的依据和步骤

**知识缺失**
- 表现：Agent的回答缺少关键信息
- 根因：Agent不知道某些私有信息

**流程不当**
- 表现：Agent的执行顺序有问题
- 根因：没有定义清晰的步骤顺序

### Step 5: 提出方案

不是加补丁，而是从结构层面解决：

| 问题类型 | 解决方案 |
|----------|----------|
| 边界问题 | 在Prompt中明确定义边界，用"做/不做"清单 |
| 判断问题 | 增加判断结构，给出决策依据和步骤 |
| 知识问题 | 补充特定的私有知识 |
| 流程问题 | 重新设计执行步骤的顺序 |

### Step 6: 验证

问自己：

- 这个方案解决的是根本问题还是表面问题？
- 实施后Prompt会变简单还是复杂？
- 这个方案能预防类似问题再次发生吗？

## 三、诊断式Prompt模板

可以直接使用这个Prompt来辅助诊断：

```markdown
# Prompt诊断助手

## 你的角色
你是一个Prompt诊断专家。用户会描述Agent的问题，你的任务不是直接给解决方案，而是先诊断问题的本质。

## 核心原则
- 永远先诊断，后开方
- 症状不是问题，要找到根因
- 简化优于复杂化
- 如果不确定，继续追问

## 诊断流程

### 当用户描述问题时：

1. **复述确认**
   "你说的是：[复述问题]，对吗？"

2. **追问上下文**（每次只问一个）
   - 这个问题是偶尔发生还是总是发生？
   - 能给我一个具体的例子吗？
   - 当时的输入是什么？期望的输出是什么？实际的输出是什么？

3. **寻找模式**
   - 这个问题和之前遇到的其他问题有关联吗？
   - 你之前加过类似的补丁吗？效果如何？

4. **定位根因**
   判断问题属于哪一类：
   - 边界不清：Agent不知道什么该做什么不该做
   - 判断逻辑缺失：Agent不知道如何在模糊情况下决策
   - 知识缺失：Agent缺少必要的私有信息
   - 流程不当：Agent的执行顺序有问题

5. **提出方案**
   - 边界问题 → 建议调整边界定义
   - 判断问题 → 建议增加判断结构
   - 知识问题 → 建议补充特定知识
   - 流程问题 → 建议调整步骤顺序

6. **验证**
   - 这个方案解决的是根本问题还是表面问题？
   - 实施后Prompt会变简单还是复杂？
```

## 四、实例演示

### 案例1：回答太长

**用户说：** "我的Agent总是回答太长，我想让它简洁一点。"

**❌ 补丁式回应：**
```
在Prompt里加一条：回答要简洁，不超过100字。
```

**✅ 诊断式回应：**

**Step 1 - 复述确认：**
"你说Agent回答太长，想让它简洁。我先了解一下具体情况。"

**Step 2 - 追问上下文：**
"是所有回答都太长，还是某些类型的问题回答太长？"

（用户说：解释概念时太长，举例时还好）

**Step 3 - 寻找模式：**
"你之前有没有加过类似的限制？比如字数限制？"

（用户说：加过，但效果不好，有时候该详细的地方也被截断了）

**Step 4 - 定位根因：**
这是一个**判断问题**，不是边界问题。Agent不知道什么时候该简洁，什么时候该详细。

**Step 5 - 提出方案：**
"问题不是'回答太长'，而是'Agent不知道该说多少'。

建议在思维结构里加一个判断逻辑：

```
解释概念时：
1. 先给一句话定义
2. 问用户是否需要展开
3. 如果需要，再给详细解释
```

这样Agent就有了判断依据，而不是机械地限制字数。"

**Step 6 - 验证：**
"这个方案让Prompt更简单还是更复杂？"
→ 更简单，因为它用一个判断结构替代了多个字数限制规则。

---

### 案例2：不遵守格式

**用户说：** "我让Agent用JSON格式输出，但它经常输出不规范的JSON。"

**❌ 补丁式回应：**
```
加一条：必须输出有效的JSON格式，不要有多余的文字。
```

**✅ 诊断式回应：**

**Step 2 - 追问上下文：**
"能给我一个具体的例子吗？它输出了什么？"

（用户说：它会在JSON前面加一句"好的，这是结果："）

**Step 4 - 定位根因：**
这是一个**边界问题**。Agent不知道"只输出JSON"意味着什么。

**Step 5 - 提出方案：**
"问题是边界不清晰。建议明确定义：

```
输出格式：
- 只输出JSON，不要有任何其他文字
- 不要有开场白、解释、结束语
- 直接以 { 开头，以 } 结尾
```

或者更简洁：
```
输出：纯JSON，无其他内容
```
"

## 五、自检清单

每次修改Prompt前，问自己：

- [ ] 我理解问题的根因了吗？还是只看到了症状？
- [ ] 这个修改是在解决结构问题还是在打补丁？
- [ ] 修改后Prompt会变简单还是复杂？
- [ ] 这个修改能预防类似问题再次发生吗？
- [ ] 有没有可以合并或删除的规则？

---

## 六、总结

**诊断式Prompt工程的道：**

1. 不接受表面问题，追问本质
2. 分类问题：边界、判断、知识、流程
3. 从结构层面解决，而不是堆叠规则
4. 简化是目标，复杂是警告

**记住：**
- 补丁是症状，不是治疗
- 好的Prompt应该越改越简单
- 如果你在不断加规则，说明结构有问题
